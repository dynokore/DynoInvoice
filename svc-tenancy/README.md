## Repository gates (`./gradlew check`)

- **`acKeyCoverage`**: `ac-keys.tsv` lists the acceptance criteria of this service's tasks (criterion, task, wave). Fails
  when the table is missing, empty or malformed, when a wave-2 row has no test whose name holds its key as a whole token,
  or when a test name holds a key that is in no row. Every later task appends the rows of its own criteria.
- **`operationsGate`**: `operations.tsv` lists every operationId and channel of the contract with the task that
  implements it and its state. Fails when the contract holds one the table lacks, when the task cell differs from the
  ruled assignment, or when a `done` row still answers 501 (an operation) or has no payload-schema test (a channel).
- **Architecture** (`ArchitectureTest`): the layer rule, jOOQ-only database access, the SQL guards and the migration lint.

## Dependency locking and verification (STK-72)

Every resolvable configuration of every project is locked in strict mode (`gradle.lockfile` per module,
`buildscript-gradle.lockfile`, `gradle/settings-gradle.lockfile`) and every downloaded artefact is verified against
`gradle/verification-metadata.xml`. No build file or CI job turns verification off. When a dependency or plugin
changes, use an empty Gradle user home and write the locks and the metadata in one pass:

```sh
./gradlew resolveAndLockAll compileKotlin compileTestKotlin spotlessCheck checkDependencyCatalogUsage verifyBannedDependencies \
  -x test --continue --write-locks --write-verification-metadata sha256,pgp --export-keys --no-configuration-cache
```

## Owns

Tenants, groups, entities and business units; entity profiles and their history; period records and extensions; workspaces; certification status; entitlement and metering counters; licence status; questionnaire answers and the applied operating profile (FR-AI.7, FR-AI.8); installation facts — release train and supported window, backup-target verification (FR-H.23), installation platform (VP-52), heartbeat target (FR-AE.70)

## Provides

Structure queries that fill replica cache misses (FR-AH.4). Profile, calendar and workspace commands to console-bff. Tenant provisioning and usage counters for billing (FR-G.11) to control-plane-svc (SaaS)

## Capabilities

The four-level hierarchy (FR-G.1). Entity lifecycle: create, go-live gate (FR-Q.16), suspend, deregister, offboarding checks (FR-AB.9). The entity profile, effective-dated: constitution, registration period, filing-frequency history, obligation start, Excluded Business and partial-exemption status, elections, issuance mode, rendition responsibility (§33.1, §33.5, §33.7, §35.4). Phase assessment. Period calendar generation, filing due dates under the calendar pack and the non-business-day rule (VP-62), and recorded extensions (§35.3). Workspaces and their pairing (§35.5). Certification status (§35.8). Entitlement, metering and licence status (FR-G.11, FR-G.12)

## Must not

- Hold grants, consents, principals or any other authority data (AD-20)
- evaluate authorisation
- block submission on an entitlement limit or an expired licence (FR-G.12, FR-H.4)
- compute a submission due date — it records period dates and extensions, and submission-svc recomputes
