## Repository gates (`./gradlew check`)

- **`acKeyCoverage`**: `ac-keys.tsv` lists the acceptance criteria of this service's tasks (criterion, task, wave). Fails
  when the table is missing, empty or malformed, when a wave-2 row has no test whose name holds its key as a whole token,
  or when a test name holds a key that is in no row. Every later task appends the rows of its own criteria.
- **`operationsGate`**: `operations.tsv` lists every operationId and channel of the contract with the task that
  implements it and its state. Fails when the contract holds one the table lacks, when the task cell differs from the
  ruled assignment, or when a `done` row still answers 501 (an operation) or has no payload-schema test (a channel).
- **Architecture** (`ArchitectureTest`): the layer rule, jOOQ-only database access, the SQL guards and the migration lint.

## Dependency locking and verification (STK-72)

Every resolvable configuration of every project is locked in strict mode (`gradle.lockfile` per module,
`buildscript-gradle.lockfile`, `gradle/settings-gradle.lockfile`) and every downloaded artefact is verified against
`gradle/verification-metadata.xml`. No build file or CI job turns verification off. When a dependency or plugin
changes, use an empty Gradle user home and write the locks and the metadata in one pass:

```sh
./gradlew resolveAndLockAll compileKotlin compileTestKotlin spotlessCheck checkDependencyCatalogUsage verifyBannedDependencies \
  -x test --continue --write-locks --write-verification-metadata sha256,pgp --export-keys --no-configuration-cache
```

## Environment (INV-REQ-502)

`inv.tenancy.environment` is `PRODUCTION` or `SANDBOX` and has no default: a start without it, or with any other value,
fails during start-up. A SANDBOX workspace of the SaaS form is a tenant row (`environment`, `paired_production_tenant_id`,
`workspace_name`); a credential is accepted only when its own environment tag equals the target's environment. The target is SANDBOX when the tenant row says SANDBOX or the service was started as
SANDBOX, else PRODUCTION (INV-Q-11905 A). The operations `loadCredential`, `recordSampleApproval` and `requestSampleCopy`
refuse with TNC-005, TNC-006 and TNC-007 (422); the two sample operations are decided by the permission keys
`sample-copy.approve` and `sample-copy.request` through `AuthorityReplica.decideTenant`, never by a role name.

## Backdating floor of VP-62 (INV-Q-16675 A, INV-AC-16774)

`tenancy.despatch_fact` is the replica of `SubmissionDespatched` (topic `gst.submission.submission-despatched.v1`): one
row per tenant and entity ref with `first_despatched_at` and `doc_uuid`, and no other column. An event without
`entityref` or `tenantid` is dead-lettered by the shared envelope reader. The inbox consumer of its own (`SubmissionDespatchedConsumerConfiguration`) reads envelope
attributes only and keeps the first fact. `TenancyBackdatingFloor`, wired by `BackdatingFloorConfiguration`, binds the
config-resolver port `BackdatingFloor` for the key of `TenancyVariationPoints.NON_BUSINESS_DAY_RULE` and the levels
ENTITY and CLIENT_ENTITY: it answers the `obligation_start_date` of the latest OBLIGATION_START row of the entity, and
null (back-dating refused) when the replica holds a fact for the entity, for every other key and
level, an unknown entity, an entity without that row, and on any exception (fail closed).

## Secrets (STK-29)

`tenancy/period-list-cursor-key` (at least 32 bytes) signs the `listPeriodRecords` cursor (HMAC-SHA256, INV-Q-16673); it is read
through the secret store at every use. The optional `tenancy/period-list-cursor-key-previous` is accepted for verification
only, so a rotation keeps issued cursors valid for their 24 hours. A missing or short current key makes a paged read fail
with a 5xx; there is no unsigned fallback. The deployment values that mount the secret are not in this repository.

## Synchronous calls

None

The documents-count port of offboarding (`offboardTenant`, `closeTenant`, `deregisterEntity`) reads a replica in the own database that the consumer of `UnsubmittedDocumentCountMeasured` fills (`ReplicaUnsubmittedDocuments`, INV-REQ-956). The service still makes no synchronous call. A count older than `inv.offboarding.unsubmitted-count.max-age`, a missing one, or an unreadable one refuses the offboarding 422 POL-014 naming `unsubmitted-documents-count`.

The export of `offboardTenant` and `closeTenant` is asynchronous (INV-AC-22961). The `TenantExport` port is the outbox publisher: the request stores one REQUESTED record and one `OffboardingExportRequested` outbox row in one transaction and answers 202, and the tenant stays OPEN. The consumer of `OffboardingExportFinished` moves the record to COMPLETED (a tenant record then closes the tenant) or FAILED (the tenant stays OPEN and a new request is accepted). A REQUESTED record older than `tenancy.offboarding.export-timeout` (ISO-8601 duration, default `PT24H` in `application.yaml`, read once at start; an unparsable or non-positive value fails the start) is FAILED when the next request for that scope finds it.
